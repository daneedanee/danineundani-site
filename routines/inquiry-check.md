# 매일 아침 상담 신청 확인 — COO 점검 지시서

이 문서는 Claude Code 클라우드 루틴이 혼자 읽고 실행하는 지시서입니다.
매일 오전 8시 7분(한국 시간)에 한 번 돕니다. 사람에게 물어볼 수 없으니, 여기에 없는 판단이 필요하면 추측하지 말고 멈추고 보고합니다.

## 무엇을, 왜

다니는다니 홈페이지(www.daneedanee.com)의 상담 신청 양식으로 **새 신청이 들어왔는지**를 확인해 대표에게 알립니다.
대표가 매번 직접 확인하던 일입니다. 신청을 놓치면 답이 늦어집니다.

이 루틴은 **상태를 확인하는 역할(COO)** 입니다. 업무를 처리하지 않습니다.
신청 내용을 읽거나, 답장을 쓰거나, 무엇을 고치지 않습니다. **건수만** 확인합니다.
신청 내용은 대표가 직접 관리자 화면에서 봅니다.

## 입력

환경 변수 두 개를 씁니다. 둘 다 홈페이지에 공개된 값이고 비밀이 아닙니다.

- `SUPABASE_URL` — Supabase 프로젝트 주소
- `SUPABASE_KEY` — 방문자용(publishable) 키

부르는 곳은 함수 하나뿐입니다: `cab_new_inquiry_count(since)`.
기준 시각 뒤에 들어온 신청의 **건수**와 **가장 최근 시각**만 돌려줍니다. 이름·이메일·내용은 돌려주지 않습니다.
함수의 정의는 이 저장소의 `supabase/06-new-inquiry-count.sql`에 있습니다.

## 처리 순서

1. 환경 변수 `SUPABASE_URL`과 `SUPABASE_KEY`가 비어 있지 않은지 확인합니다. 하나라도 비어 있으면 **중단**합니다.

2. 지난 24시간의 건수를 묻습니다.

   ```bash
   SINCE=$(date -u -d '24 hours ago' +%Y-%m-%dT%H:%M:%SZ)
   curl -sS --max-time 20 -w '\nHTTP %{http_code}\n' -X POST "$SUPABASE_URL/rest/v1/rpc/cab_new_inquiry_count" \
     -H "apikey: $SUPABASE_KEY" -H "Authorization: Bearer $SUPABASE_KEY" \
     -H "Content-Type: application/json" \
     -d "{\"since\":\"$SINCE\"}"
   ```

   정상 응답은 `HTTP 200`이고 본문은 이런 꼴입니다: `[{"new_count":2,"latest_at":"2026-10-12T01:23:45.678+00:00"}]`
   신청이 없으면 `[{"new_count":0,"latest_at":null}]` 입니다.

3. 같은 방법으로 지난 7일의 건수도 한 번 묻습니다 (`'7 days ago'`). 하루 실행이 빠졌을 때 놓친 신청이 있는지 보기 위한 것입니다.

4. 아래 「보고」 형식대로 마지막 답변을 쓰고 끝냅니다.

## 실패했을 때

- 요청이 실패하면(연결 오류, 시간 초과, `HTTP 200`이 아닌 응답, 본문이 위의 꼴이 아님) **30초 기다린 뒤 한 번만** 다시 시도합니다.
- 두 번째도 실패하면 **중단**하고 「확인 못 함」으로 보고합니다.
- 실패를 「새 신청 없음」으로 적지 않습니다. 확인하지 못한 것과 0건은 다릅니다.
- 다른 길을 찾지 않습니다. 아래 「하지 않는 일」을 봅니다.

## 보고

결과를 파일로 저장하지 않습니다. **이 실행의 마지막 답변이 곧 보고**입니다. 대표가 루틴 실행 화면에서 읽습니다.
시각은 한국 시간(UTC+9)으로 바꿔 적습니다. 아래 셋 가운데 하나를 그대로 씁니다.

새 신청이 없을 때:

```
[상담 신청 확인] 2026-10-12 08:07 기준
지난 24시간: 새 신청 없음
지난 7일: N건
```

새 신청이 있을 때:

```
[상담 신청 확인] 2026-10-12 08:07 기준
지난 24시간: 새 신청 N건 (가장 최근 10월 12일 10:23)
지난 7일: N건
확인: https://www.daneedanee.com/admin
```

확인하지 못했을 때:

```
[상담 신청 확인] 2026-10-12 08:07 기준
확인 못 함
까닭: (받은 오류를 그대로. 예: HTTP 403 host_not_allowed)
한 일: 두 번 시도 후 중단
```

## 하지 않는 일

- `cab_inquiries` 표를 직접 읽지 않습니다. 위 함수만 부릅니다.
- 서비스 키나 다른 키, 다른 주소, 다른 방법을 찾지 않습니다. 막히면 멈춥니다.
- 이 저장소의 파일을 고치거나 만들지 않습니다. 커밋·푸시·풀 리퀘스트를 하지 않습니다.
- 메일·메시지를 보내지 않습니다. 무엇도 게시·발송·삭제하지 않습니다.
- 커넥터를 쓰지 않습니다 (이 루틴에는 커넥터가 연결돼 있지 않아야 합니다).
- 신청자에게 연락하지 않습니다. 신청 내용을 추측해 적지 않습니다.

## 중단 조건 (하나라도 해당하면 멈추고 보고)

- 환경 변수가 비어 있다.
- 두 번 시도해도 정상 응답을 받지 못했다.
- 응답의 꼴이 이 문서와 다르다.
- 이 문서에 없는 판단이 필요하다.
